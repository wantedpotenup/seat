# 교육생 자리 번호 선택 웹앱

교육장 공용 화면에 띄워두고, 참가자가 1~N번 중 원하는 번호를 직접 선택하는 웹앱입니다.
기본적으로는 선택된 `이름 + 번호`만 저장하고, 실제 좌석 매칭은 운영자가 별도로
처리합니다. 다만 원한다면 관리자 화면에서 실제 교육장 모양의 좌석 배치도를 입력해둘
수 있고, 그러면 참가자들이 "자리 확인하기" 결과 화면에서 실제 자리 모양 그대로(이름
포함) 확인할 수 있습니다 (5번 참고). 이 기능은 선택사항이며, 설정하지 않으면 번호
순서대로 나열된 기본 화면이 표시됩니다.

## 기술 스택

- Frontend: React + TypeScript + Vite + Tailwind CSS
- Database / 백엔드: Google Sheets + Google Apps Script (Web App)
- 배포: Vercel

> 원래는 Supabase(Postgres)를 백엔드로 사용했는데, 무료 프로젝트 개수 제한 때문에
> Google Sheets + Apps Script 로 옮겼습니다. 완전히 무료이고 별도 계정 생성 없이
> 이미 있는 Google 계정으로 바로 만들 수 있습니다. 대신 진짜 실시간(realtime)이
> 아니라 몇 초마다 자동으로 다시 조회하는 방식(polling)이라 아주 약간의 지연이
> 있습니다 (기본 4초).

## 1. Google Sheets + Apps Script 백엔드 준비

1. [sheets.google.com](https://sheets.google.com) 에서 새 스프레드시트를 만듭니다.
   (이름은 자유롭게, 예: "자리번호 선택 데이터")
2. 상단 메뉴 **확장 프로그램 → Apps Script** 를 클릭합니다. 새 탭에 스크립트
   편집기가 열립니다.
3. 편집기에 기본으로 있는 `myFunction() {}` 같은 코드를 전부 지우고, 이 저장소의
   `apps-script/Code.gs` 파일 내용 전체를 복사해서 붙여넣습니다.
4. 저장(💾) 후, 상단의 함수 선택 드롭다운에서 **setup** 을 고르고 ▶ 실행 버튼을
   누릅니다.
   - 처음 실행하면 "권한 승인 필요" 창이 뜹니다. **권한 검토** → 본인 계정 선택 →
     "이 앱은 Google에서 확인하지 않았습니다" 화면에서 **고급** → **(프로젝트
     이름)(안전하지 않음)으로 이동** → **허용** 을 눌러야 합니다. 본인이 만든
     스크립트이므로 안전합니다.
   - 실행이 끝나면 스프레드시트로 돌아가서 `Seats`, `Config` 라는 시트 탭 2개가
     새로 생긴 것을 확인합니다.
5. **반드시 관리자 비밀번호를 변경하세요.** `Config` 시트를 열어 `AdminPassword`
   행의 값을 `change-me-1234` 에서 원하는 비밀번호로 바로 수정하면 됩니다 (별도
   저장 버튼 없이 셀 값만 바꾸면 즉시 적용됩니다).
6. Apps Script 편집기에서 **배포 → 새 배포** 를 클릭합니다.
   - 유형 선택(⚙️ 아이콘) → **웹 앱**
   - 설명: 아무거나 (예: "seat-picker v1")
   - 실행할 사용자: **나**
   - 액세스 권한이 있는 사용자: **전체 공개(모든 사용자)**
   - **배포** 클릭 → 권한 승인이 다시 뜨면 5번과 동일하게 허용
7. 배포가 끝나면 나오는 **웹 앱 URL** (`https://script.google.com/macros/s/.../exec`
   형태)을 복사해둡니다. 이 URL이 프론트엔드가 호출할 API 주소입니다.

> ⚠️ 이 스프레드시트에 "편집 권한"을 준 사람은 `Config` 시트에서 관리자 비밀번호를
> 볼 수 있습니다. 이 시트는 절대 다른 사람과 공유하지 마세요. 참가자에게는
> 배포된 **웹사이트** 주소만 알려주면 되고, 이 스프레드시트에 접근할 필요가
> 전혀 없습니다.

> 코드를 수정하고 다시 배포할 때는 "새 배포"가 아니라 **배포 관리 → 기존 배포
> 옆 ✏️ 편집 → 버전: 새 버전 → 배포** 를 눌러야 URL이 바뀌지 않습니다.

## 2. 로컬 환경 설정

```bash
npm install
cp .env.example .env
```

`.env` 파일을 열어 1번에서 복사한 웹 앱 URL을 넣습니다.

```
VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/여기에-배포ID/exec
```

로컬에서 실행:

```bash
npm run dev
```

## 3. 첫 사용 전 설정 (좌석 개수 지정)

1. 브라우저에서 `/admin` 페이지로 이동합니다.
2. 방금 설정한 관리자 비밀번호로 로그인합니다.
3. "좌석(번호) 개수 설정"에 참가자 수(N)를 입력하고 **생성 / 초기화** 를 누르면
   1번부터 N번까지 번호가 생성됩니다. 과정마다 참가자 수가 바뀌면 이 화면에서
   다시 설정하면 됩니다 (기존 선택 결과는 모두 초기화됩니다).

## 4. 사용 흐름

- **참가자**: `/` 메인 화면에서 원하는 번호 클릭 → 선택 확인 → 이름 입력 → 선택 완료.
  결과는 몇 초 안에 모든 접속자의 화면에 반영됩니다. 메인 화면 하단의 "자리
  확인하기" 버튼은 관리자가 결과를 공개하기 전까지는 비활성화되어 있습니다.
- **운영자**: `/admin` 에서 전체 선택 현황(순서/이름/번호/시간)을 확인할 수
  있습니다 (같은 내용이 스프레드시트의 `Seats` 탭에도 그대로 보입니다). 새로운
  과정을 시작할 때는 "전체 초기화"를 눌러 선택 결과만 지우거나(번호는 유지),
  참가자 수가 달라졌다면 "좌석 개수 설정"으로 다시 생성합니다.

## 5. 자리 확인하기 결과 공개 & 좌석 배치도 (선택사항)

`/admin` 화면에는 두 가지 추가 설정이 있습니다.

- **좌석 배치도 설정**: 실제 교육장 모양대로 텍스트로 입력해두면, 참가자가 나중에
  결과를 확인할 때 실제 자리 모양 그대로 보여줍니다. 한 줄이 한 행이고, 칸은 쉼표(,)로
  구분합니다.
  - 숫자 → 그 번호의 좌석
  - 빈 칸 (쉼표만 연속) → 통로 등 빈 공간
  - `X` → 사용할 수 없는 칸 (기둥, 벽 등)
  - 그 외 텍스트 → 라벨 칸 (예: `강사`)

  예시 (열 사이에 통로를 두려면 빈 칸을 하나 넣으면 됩니다):

  ```
  16,7,25,,8,19,X
  4,23,13,,3,10,22
  20,11,21,,2,24,14
  9,17,5,,12,18,6
  X,X,1,,15,X
  ```

  입력 후 "배치도 저장"을 누르면 바로 아래 미리보기에서 확인할 수 있습니다.
  설정하지 않으면 번호 순서대로 나열된 기본 그리드가 대신 표시됩니다.

- **결과 공개**: 참가자들이 선택을 모두 마친 뒤 "결과 공개하기"를 누르면, 그 순간부터
  모든 참가자의 메인 화면에서 "자리 확인하기" 버튼이 활성화되어 배치도(또는 기본 그리드)
  결과를 볼 수 있습니다. 좌석 개수를 다시 설정하거나 전체 초기화를 하면 자동으로
  비공개 상태로 돌아갑니다.

## 6. Vercel 배포

1. 이 프로젝트를 GitHub 저장소로 푸시합니다.
2. [vercel.com](https://vercel.com) 에서 New Project → 해당 저장소를 선택합니다.
   Framework Preset 은 Vite 로 자동 인식됩니다.
3. **Environment Variables** 에 아래 값을 추가합니다.
   - `VITE_APPS_SCRIPT_URL`
4. Deploy 를 누르면 배포가 완료됩니다. 이후 발급된 URL을 교육장 공용 화면과
   참가자들에게 공유하면 됩니다.

## 참고: Apps Script 사용량 관련 주의사항

Google 계정(무료 개인 계정 기준)은 Apps Script 하루 실행 시간 총합에 제한이
있습니다(대략 하루 90분). 참가자가 아주 많거나(수백 명) 화면을 며칠씩 계속 띄워두는
방식이 아니라, 한 번의 교육 과정(보통 몇십 명, 몇십 분 이내) 동안 쓰는 용도라면
문제없는 수준입니다. 혹시 "서버가 응답하지 않는다"는 오류가 자주 보이면:

- `src/hooks/useAppData.ts` 의 `POLL_MS` 값을 4000(4초)에서 더 크게(예: 8000)
  늘려서 재조회 빈도를 줄일 수 있습니다.
- 회사/학교 Google Workspace 계정으로 스프레드시트를 만들면 개인 계정보다 훨씬
  넉넉한 한도가 적용됩니다.

## 프로젝트 구조

```
src/
  lib/api.ts                Apps Script 웹 앱 호출 함수 모음
  lib/seatLayout.ts          배치도 텍스트 <-> JSON 변환 유틸
  hooks/useAppData.ts        좌석/설정/배치도 조회 + polling
  components/                SeatGrid, SeatCard, SeatLayoutGrid, 각종 모달
  pages/MainPage.tsx         참가자용 메인 화면 (/)
  pages/AdminPage.tsx        관리자 화면 (/admin)
  pages/ResultsPage.tsx      자리 확인 결과 화면 (/results)
apps-script/Code.gs          Google Apps Script 백엔드 (스프레드시트에 붙여넣어 사용)
```

## 참고: 이 앱이 하지 않는 것

- 번호-실제 좌석 매칭은 기본적으로 저장하지 않습니다. 관리자가 원할 때만 배치도를
  입력해서 참가자에게 공개할 수 있고, 입력하지 않으면 실제 좌석 정보는 전혀 다루지
  않습니다.
- 참가자용 로그인 시스템이 없습니다 (누구나 접속해 이름과 번호만 입력).
- 진짜 실시간(realtime) push는 아닙니다 — 몇 초 간격으로 자동 재조회(polling)하는
  방식입니다.
